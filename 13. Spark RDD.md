## What does RDD stand for and how does it work?

RDD stands for Resilient Distributed Dataset. It is a fundamental concept in Apache Spark that enables high-speed, parallel processing of large-scale data.

What RDD Stands For

• Resilient: Refers to the system being fault-tolerant. If a task fails or data is lost in memory, the system can recover or "tolerate" that fault.

• Distributed: The input data is not kept as one single file; instead, it is divided into partitions and spread across the memory of multiple nodes (machines) in a cluster.

• Dataset: This is the actual data you provide as input, which could be in formats like JSON, CSV, or Avro.

How RDD Works
The sources describe the workflow of an RDD through the following key mechanisms:
1. **Data Partitioning and In-Memory Storage** When a Spark job starts, it reads the input file and divides it into smaller partitions (e.g., B0, B1, B2). These partitions are then distributed across the memory (RAM) of different nodes. Storing data in memory is a critical feature of Spark that allows for faster processing compared to disk-based systems.

2. **Transformations and Chaining** Users write programs consisting of transformations (such as map or filter).
• Spark can run multiple transformations in a sequence where the output of the first transformation serves as the input for the next.
• By default, the intermediate outputs of these transformations are also stored in the Spark memory across the nodes.

3. **Data Lineage and the DAG** Spark maintains a "lineage" (similar to a family tree) of all transformations performed on the data. This lineage is managed using a Directed Acyclic Graph (DAG), which is a graph algorithm that tracks every step the data has gone through.
4. **Fault Tolerance through Recomputation** If a specific node crashes or a piece of data is lost from memory, Spark does not need to restart the entire job. Instead:
• It refers to the lineage/DAG to identify which transformation created the lost data.
• It recomputes only that specific missing task, saving significant time.
5. **Persistence and Replication** While Spark stays in memory by default, users can use a feature called "Persist" to store data more permanently in memory, on disk, or both. You can also set a replication factor (e.g., MEMORY_ONLY_2), which creates two copies of the data in memory. This allows Spark to quickly grab the backup copy if one fails, rather than having to recompute it.
6. **Operations:** Transformations and Actions The code written for RDDs is generally divided into two types of operations: Transformations (which define the processing logic) and Actions (which trigger the execution). Even in newer Spark versions, such as those using DataFrames or Datasets, RDD remains the underlying engine that performs the partitioning, distribution, and fault-tolerance work
