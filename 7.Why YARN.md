***Hadoop 1.x:***

🔴 No YARN

Hadoop 1 uses MRv1 (MapReduce v1)

JobTracker (single master): Resource management, Job scheduling, Task monitoring

TaskTracker (on each node): Executes map & reduce tasks

❌ Problems
Single point of failure (JobTracker)
Poor scalability
Only MapReduce supported (no Spark, Tez, etc.)

📌 YARN does NOT exist in Hadoop 1

***Hadoop 2.x***

🟢 YARN introduced

YARN = Yet Another Resource Negotiator

Architecture

ResourceManager (RM) – cluster-wide resource manager
NodeManager (NM) – runs on each node
ApplicationMaster (AM) – per application (MapReduce AM for MR jobs)
Containers – resource units (CPU + memory)

MapReduce in Hadoop 2

MapReduce rewritten as MRv2

JobTracker split into: ResourceManager, ApplicationMaster

✅ Benefits

Better scalability

Multiple frameworks supported:MapReduce, Spark, Hive, Tez

High Availability supported

***Hadoop 3.x***

🟢 YARN enhanced (not redesigned)

Same core architecture as Hadoop 2, but improved.

Enhancements

Better resource utilization

GPU & FPGA scheduling support

Improved container isolation (Docker support)

More scalable ResourceManager

Multiple active NameNodes (HDFS improvement)

MapReduce in Hadoop 3

Still MRv2 on YARN

Faster execution

More stable at scale
