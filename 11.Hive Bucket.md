## 1️⃣ What is Hive Bucketing?
    
Bucketing divides data inside a Hive table into a fixed number of files called buckets, based on a hash of a column.

**How it works**

  ->You choose a bucket column

  ->Hive applies a hash function on that column

  ->Rows with the same hash go into the same bucket file

  <img width="586" height="68" alt="image" src="https://github.com/user-attachments/assets/cff87a11-d65e-4d17-84d7-9bda2a637d9f" />

**📦 Result:**

-> Exactly 8 files (buckets) per partition (or per table if no partition)

-> Bucket number is deterministic (same value → same bucket)

**Why buckets exist**

-> Faster joins

-> Faster sampling

-> Better query optimization (especially with map-side joins)


## 2️⃣ Why NOT always use Partitioning?

Partitioning is powerful, but it has downsides when overused.

**What partitioning does**

--> Physically separates data into directories

--> Each unique partition value = new folder

<img width="520" height="188" alt="image" src="https://github.com/user-attachments/assets/b222ffa1-2a09-44d3-b6f7-f2adb5df1b4c" />

**Problems with partitioning**

***❌ Too many partitions***

If partition column has high cardinality (user_id, order_id)

Millions of folders → NameNode overload

****❌ Small file problem***

Each partition may contain tiny files

Bad for HDFS & performance

***❌ Slower metadata operations***

Hive must track every partition

## 3️⃣ Why Bucketing instead of Partitioning?

Bucketing solves problems that partitioning can’t.

**Bucketing advantages**

✅ Handles high cardinality columns
✅ Avoids millions of directories
✅ Improves joins & sampling
✅ Fixed number of files (predictable)
