**How does the master-slave architecture manage data distribution and fault tolerance through replication?**

In a master-slave architecture like the Hadoop Distributed File System (HDFS), data distribution and fault tolerance are managed through a centralized control system that coordinates how data is divided, stored, and recovered across a cluster of machines.

Data Distribution via Blocks
When a file is uploaded to the system, it is not stored as a single large file. Instead, it is managed as follows:

• Block Splitting: The file is divided into small partitions called blocks. In older versions of Hadoop, the default block size was 64 MB, while in newer versions it is 128 MB.

• Distribution Strategy: These blocks are distributed across multiple Slave nodes (DataNodes). The Master node (NameNode) does not store the actual data; instead, it generates metadata, which acts as a map showing which blocks belong to which file and where they are located.

• Placement Allocation: The Master uses a "rack awareness policy" to decide which specific slave nodes will receive which blocks, ensuring the data is spread logically across the infrastructure.

Replication for Fault Tolerance
Fault tolerance—the ability of the cluster to continue operating despite failures—is primarily achieved through replication.

• The Default Rule: For every block of data, the system typically maintains three replicas. This means for a 1GB file, the system requires 3GB of hard disk space to ensure safety.

• Redundancy Rule: A critical rule of this architecture is that copies of the same block cannot reside on the same node. If a node fails, the data remains accessible because copies exist on other machines.

• The Pipeline: During the data writing process, a pipeline is created to transfer blocks to the assigned slave nodes. If a slave node fails during this process, the Master immediately updates the metadata to redirect the data to a healthy node.

Managing Failures
The Master-Slave architecture uses constant communication to detect and fix issues:

• Heartbeats: Every three seconds, slaves send a "heartbeat" to the Master to signal they are alive. If the Master stops receiving heartbeats from a node, it marks that node as "dead".

• Automatic Failover: Once a node is confirmed dead, the Master identifies which blocks were lost and triggers an automatic failover. It finds the remaining replicas of those blocks on other healthy nodes and copies them to new nodes to restore the required number of replicas.

• High Availability (HA): In older versions, the Master was a "single point of failure" (if it died, the whole cluster was lost). Modern architectures (Hadoop 2 and 3) support High Availability, allowing for an Active Master and one or more Passive Masters. If the Active Master fails, a technology called Zookeeper elects a Passive Master to take over immediately.

To visualize this, imagine a construction site where one Foreman (Master) holds the blueprints and tells a team of Laborers (Slaves) where to stack bricks. If a Laborer gets sick, the Foreman sees they aren't checking in, looks at the blueprints to see what bricks that person was carrying, and assigns a new Laborer to fetch copies of those same bricks from a backup pile to keep the project moving.
